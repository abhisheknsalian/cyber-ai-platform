# Release Notes

A capability summary by subsystem, not a commit log — see `git log` for the full chronological
history. This describes the state of the repository at the end of its final engineering phase.

## Frontend

React (Vite + TypeScript + Tailwind) single-page dashboard: login-gated routing, a threat-analysis
query page, a network-traffic classification page, a threat-intelligence graph view, and an about
page. Talks to the backend directly (cross-origin, credentialed requests), not through a proxy.
Served in production by an nginx container built from the static `vite build` output.

## Backend API

FastAPI service exposing 14 endpoints across three groups: public (`/`, `/health`, `/ready`,
`/threats`, `/intelligence/entities`, `/intelligence/graph/{threat_id}`), authentication
(`/auth/login`, `/auth/logout`, `/auth/me`), and protected (`/analyze`, `/classify`,
`/ml/feature-importance`, `/analyze/classification`, `/intelligence/search`). See README **Backend
Endpoints** and **Authentication** for the exact, current, verified list.

## ML detection

Random Forest classifier trained on real CICIDS2017 network-flow data (BENIGN/DDoS, 78-feature
CICFlowMeter-style schema), with a duplicate-removal leakage-prevention fix in preprocessing. The
schema, metrics, and prediction-mapping layer are multi-class-*ready* (dynamic `LABEL_MAP`-driven
validation, per-class probabilities) without a second class actually trained — see README
**Multi-class-ready architecture (Phase 10)** for exactly what real data a genuine multi-class model
would need.

## RAG & retrieval

Chroma vector store over sentence-transformers embeddings of a small curated threat-intelligence
knowledge base, with a relevance threshold that keeps out-of-domain queries from ever reaching the
LLM. MITRE ATT&CK technique IDs and source attribution are extracted deterministically from the
source documents, never generated by the LLM.

## Threat intelligence graph

A deterministic, one-hop entity/relationship graph built by parsing the same source documents (no
LLM involved in construction), combined with vector retrieval into one typed "hybrid evidence"
object. The LLM's own output schema has no field for prediction, probability, MITRE ID, or source —
these cannot be overridden by generated text, not just by prompt instruction.

## LLM integration

A locally-running Llama 3.2 model via Ollama, invoked only when the deterministic retrieval/graph
layer found something genuinely relevant, and constrained to a JSON schema that excludes every field
the application treats as authoritative.

## Evaluation & benchmarking

A read-only measurement layer (`backend/evaluation/`) producing reproducible metrics against the
real local dataset and trained model: held-out vs. full-dataset classification metrics, threshold
and calibration analysis, a six-query retrieval coverage sanity benchmark, and per-stage pipeline
latency. Never trains, retrains, or modifies the production model or dataset. See README
**Evaluation & Benchmarking** for the full results table and methodology.

## Security

API-key and browser-session (HttpOnly cookie + CSRF double-submit) authentication, an explicit CORS
allowlist, IP-keyed rate limiting, request-ID correlation, structured JSON logging, and standard
security response headers. See README **Security Checklist** for the consolidated, section-linked
status of every control.

## Deployment architecture

Hardened, non-root Docker images for both services; a local-dev Compose profile and a separate,
additive production Compose profile (loopback-bound ports, read-only root filesystem where verified
safe, explicit persistent volumes); an example reverse-proxy configuration; and a documented (not
deployed) single-VM + reverse-proxy production architecture with an explicit failure-mode matrix and
scaling analysis. No real cloud resources, TLS certificates, or GPU infrastructure were provisioned
— see README **Production Deployment Architecture** for what's implemented locally versus designed
versus unverified.

## CI/CD

A GitHub Actions workflow validating the backend test suite, frontend lint/build, and both Docker
image builds on every push and pull request to `main` — using only synthetic/isolated fixtures, no
real dataset, model, or Ollama instance.

## Testing

285 automated backend tests (pytest) covering the RAG pipeline, ML pipeline, authentication,
intelligence/graph endpoints, evaluation layer, deployment configuration, and the classifier-evidence
integrity guarantees described above. No automated frontend browser test suite — the frontend was
verified manually against the real backend and Ollama.

## Known scope boundaries

This project has never been deployed to a real cloud environment. See README **Final Limitations
Summary** for the complete, categorized list — dataset scope, in-memory session/rate-limit state,
TLS not actually deployed, GPU infrastructure not provisioned, and the rest.
